# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

This is a pnpm + Turborepo monorepo. All commands are wired through Turbo at the root.

- `pnpm dev` — runs `dev` across packages (mostly `vite build --watch` in libraries; not what you want for the app)
- `pnpm build` / `pnpm lint` / `pnpm test` / `pnpm clean` — fan out via Turbo
- **Run the web app:** `pnpm --filter @whiteboard/web dev` (Vite on `:5173`)
- **Run the desktop app:** `./dev-linux.sh` on Linux (sets `WEBKIT_DISABLE_DMABUF_RENDERER=1` to work around a WebKitGTK black-screen bug); elsewhere `pnpm --filter @whiteboard/desktop dev`. Tauri's `beforeDevCommand` already spawns the web dev server.
- **Run the y-websocket server:** `pnpm --filter @whiteboard/server dev` (listens on `ws://localhost:1234`, override with `PORT`). Set `WHITEBOARD_PERSISTENCE_DIR=<path>` to persist rooms to disk (writes one `<docname>.ydoc` file per room via `Y.encodeStateAsUpdate`).
- **Build the desktop bundle:** `pnpm --filter @whiteboard/desktop build` (builds web first, then `tauri build`)
- **Mobile:** `pnpm --filter @whiteboard/mobile sync` / `ios` / `android` (Capacitor wraps `apps/web/dist`)
- **Run a single test:** `pnpm --filter @whiteboard/core test -- <pattern>` (Vitest). `packages/core` and `packages/export` are the two packages with tests today.

## Architecture

The app is an infinite whiteboard with a strict separation between a **framework-agnostic core engine** and **shell apps** that mount it.

### `packages/core` — the engine

Owns all whiteboard behavior. No React, no DOM-framework deps; consumed as a workspace lib.

- `Whiteboard` (`whiteboard.ts`) is the central class. Construct it with a `HTMLCanvasElement` and it attaches pointer/wheel/touch/keyboard/paste listeners, owns `elements`, `selectedIds`, `history`, viewport, active tool, snap config, and theme. The web app holds it in a ref.
- **Tools are pluggable** (`tools.ts`): `pan | draw | rectangle | ellipse | select | text | image | arrow`. `Whiteboard.setTool()` swaps the active `Tool` instance, which receives a `ToolContext` (viewport, elements, add/update/delete callbacks, snap helpers, etc.) on each event. Adding a new tool means: add to the `ToolType` union in `types.ts`, implement the `Tool` interface, register it in `createTool`.
- **Mutations go through `HistoryStack`** (`history.ts`). Commands (`AddElementCommand`, `DeleteElementsCommand`, `MoveElementsCommand`, `UpdateElementCommand`) are the only sanctioned way to mutate `elements` so that undo/redo works. Direct mutation (e.g. setting `wb.elements = ...` after import) bypasses history intentionally.
- **Rendering is RAF-batched** via `scheduleRender()` → one `renderer.render(...)` call per frame, with `resolveBindings()` and `resolveGroupBounds()` run first. `Renderer` (`renderer.ts`) takes a `ThemeConfig` so the canvas re-themes without CSS coupling.
- **Element types** (`types.ts`): `path | rectangle | ellipse | text | image | arrow | group`. Arrows can bind to other elements via `ArrowBinding { elementId, position }`; `resolveBindings()` re-projects bound endpoints to anchor points each frame. Groups are first-class elements with `memberIds` and computed `bounds`.
- **State persistence** is via `getState()`/`setState()` with a `STATE_VERSION` string — bump it on breaking schema changes; older blobs are silently rejected.

### `packages/collab` — Yjs + y-websocket bridge

`CollabProvider` mirrors `WBElement[]` into a `Y.Array<Y.Map>` and exposes awareness-based cursors. **Note:** the Yjs serializer in `provider.ts` enumerates element types explicitly and currently has no branch for `'group'` — adding new element types means updating both `setElements` and `addElement` here, or grouped elements won't sync.

### `packages/export` — PNG/SVG/JSON

Pure functions over `WBElement[]`. Re-uses the core renderer for PNG via an offscreen canvas.

### `apps/web` — the React shell

`App.tsx` owns toolbar/panel UI state and holds the `Whiteboard` in a ref via `Canvas.tsx`'s `onWhiteboardReady`. `useAutoSave` debounces `localStorage` writes, `useTheme` resolves light/dark with system-preference fallback, `useMediaQuery` swaps the desktop side panels for a mobile bottom sheet. Tool hotkeys (`v/h/d/r/e/a/t/i`, `Ctrl+S`) live in `App.tsx`; canvas-level shortcuts (`Ctrl+Z`, `Ctrl+G`, delete) live in `Whiteboard.onKeyDown`.

### `apps/desktop` (Tauri 2) and `apps/mobile` (Capacitor 7)

Both wrap `apps/web/dist`. Desktop uses a custom titlebar (`Titlebar.tsx`, `decorations: false` in `tauri.conf.json`). Mobile platform folders (`ios/`, `android/`) are gitignored and generated by `cap sync`.

### `server`

Wrapper around `y-websocket`'s `setupWSConnection`. By default rooms are in-memory only. If `WHITEBOARD_PERSISTENCE_DIR` is set, `src/persistence.ts` registers an fs-backed `Persistence` (`bindState` reads `<dir>/<doc>.ydoc` on first connection; `writeState` writes atomically on last disconnect). The doc name comes from the WebSocket path (`/<roomId>`) and is validated against `^[A-Za-z0-9._-]+$` to keep file paths safe. Yjs is loaded via `createRequire` in `persistence.ts` to match the CJS instance that `y-websocket` uses — don't switch it back to a static ESM import or you'll get "Yjs was already imported" warnings and broken `instanceof` checks.

## Conventions and gotchas

- **pnpm workspaces** with `workspace:*` deps everywhere. The `@whiteboard/tsconfig` package is the single source for TS config; all other packages `extends` it.
- **Libraries build via `vite build` + `vite-plugin-dts`**; the web app builds via `tsc && vite build`. The web app's `tsconfig.json` does not set `noEmit`, so `tsc` currently emits `.js`/`.d.ts`/`.map` files **into `apps/web/src/`** alongside the `.tsx` sources. Those committed emitted files are noise — don't edit them, and prefer fixing the tsconfig (`"noEmit": true`) over hand-deleting.
- **Element invariant:** every `WBElement` has `id`, `type`, `color`, `strokeWidth`. Images/groups set `color: ''`/`strokeWidth: 0` as a sentinel since they don't render strokes.
- **Adding an element type** touches at minimum: `types.ts` (union + interface), `renderer.ts`, `snap.ts` (bounds), `export/*.ts` (PNG/SVG/JSON), and `collab/provider.ts` (Yjs serialization). Forgetting collab is the easy mistake.
- **Theme:** UI chrome themes via CSS custom properties + `data-theme` on `<html>`; canvas themes via the `ThemeConfig` passed to `Renderer.render`. Element colors are **never** auto-inverted in dark mode by design.
